# 請求書 → Business仕事一覧 同期

## 目的

請求書Excelに保存済みの実績を `work_records`（Business > 月次 > 仕事一覧）へ反映する。

特に古い請求書では、以前のパーサーで `work_date` が空のまま保存された行や、
`8/2、8/3` のように1明細へ複数日が記載された行があるため、後追い同期で補正する。

## 同期ルール

- `work_date` が空の場合は、請求日と仕事内容中の日付から復元する。
- `8/2、8/3` のような複数日は日別の仕事へ分割する。
- 金額は、明細金額と単価が日数に一致する場合は単価を各日に使う。その他は明細合計を日数で分割する。
- 既に手動登録された同日の音声仕事がある場合は、同額 → 内容一致 → 金額未入力の単独候補、の順で照合する。
- 既存仕事の経費・労働時間・移動時間・メモは消さない。
- 請求ステータスは `請求済`、入金済みでなければ `未入金` にする。
- 自動で1件に決められない場合は `ambiguous` として保留し、勝手に選ばない。
- `business_invoice_work_links` で請求明細と仕事を紐付けるため、再実行しても二重登録しない。

## 実行方法

### ブラウザ

Business の `グラフ` 画面を開き、
`既存請求書 → 仕事一覧を同期` を押す。

同期前に `jarvis/backups/` へ `business_data.db` のバックアップを自動作成する。

### PowerShell

```powershell
cd C:\Users\Sunny\snowflakes\jarvis
npm run sync-invoice-work
```

2023年だけ対象にする場合:

```powershell
npm run sync-invoice-work -- 2023
```

## テスト

```powershell
npm run test-invoice-work
```

2023年明治カップ相当のケースで以下を確認する。

- `work_date = NULL` から日付復元
- 8/2・8/3、8/4・8/5 の日別分割
- 手動登録済み仕事との照合
- 2回実行しても件数が増えないこと

## グラフ

`/business-graph.html` は `work_records` を元に集計するため、手動登録と請求書同期の両方を含む。

- 年間収入
- 年間経費
- 年間利益
- 仕事件数
- 月別の収入 / 経費 / 利益
- カテゴリ別年間収入
